# Security policy

## Supported content

Security reports are accepted for the current default branch and the verification, replay, preparation, and CI tooling in the repository-owned Apache-2.0 scope. Frozen measured implementations are historical benchmark evidence and do not represent maintained production software.

## Reporting

After publication, use the repository's private security-advisory form for vulnerabilities that could expose credentials, execute untrusted content, bypass integrity checks, or write outside an explicitly selected destination. Include the affected file, reproduction steps, impact, and a minimal proof of concept. Avoid placing secrets or exploit payloads in public issues.

For a public integrity or documentation problem with no sensitive details, open a regular issue using the benchmark-problem template.
